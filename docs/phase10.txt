AUDIT AREAS (go through each one, read the actual code, and fix what is wrong)

1) Responsiveness (mobile ~375px, tablet ~768px, desktop 1280px+)
Check every storefront page and component: homepage slider + footer slide, announcement ticker, navbar, hamburger menu, search popup, cart popup, sub-category page, product listing (4 / 3 / 2 columns), filter drawer, quick view modal, product detail page (desktop 2-column grid + sticky info, below 1024px swipe slider + full-screen viewer), wishlist page, checkout, order confirmation, login/signup, Account + My Orders, footer, Contact page, Team page + member popup. Also check every admin page (sidebar drawer on mobile, tables, forms, dialogs). Look for: horizontal overflow, fixed widths, text clipping, tap targets too small, popups taller than the viewport without scrolling, wrong breakpoints, missing sizes on images, anything that breaks at 320px width.

2) Animations and touch behavior
Verify that all animations use the shared motion constants, there are no layout shifts from scroll lock, hover-only behavior is guarded so touch devices never get stuck hover states, the second-image crossfade is desktop-hover only, Buy It Now hover fill animates in and out correctly, Add to Cart styles are intact, and slider mechanics (one gesture = one slide, wheel/keyboard/touch, dot rail, footer as final slide, navbar hides on the footer slide) match AGENTS.md. Check for anything that could stutter (heavy work in scroll/animation handlers, missing will-change/transform-only animation, unnecessary re-renders in the slider).

3) Dynamic content reflection
Trace the code paths and confirm that adding, editing, or removing these in admin is reflected on the storefront everywhere they appear, with correct revalidation/caching so no stale data stays: top-level categories (homepage slides + dots, hamburger menu, search results, breadcrumbs), sub-categories (sub-category row, hamburger accordion, breadcrumbs), announcements (ticker on all pages), team members (Team carousel + member popup), products (listing, search, wishlist, cart, detail), settings/store details (footer, Contact). Confirm empty states look clean when there are zero rows (no crashes, no dummy data).

4) Discount display
Find every place a price is shown (listing card, quick view, detail page, wishlist, search results, cart popup, checkout summary, confirmation page, My Orders, admin where relevant). Confirm the original price strikethrough + discounted price + auto-calculated "X% OFF" badge is correct and consistent wherever the spec requires it, and that the percentage is rounded sensibly. Use one shared price helper/component if there is not one already; remove duplicated logic.

5) Order flow (code-level verification)
Trace both flows end to end: Add to Cart → Cart popup → Checkout → Order Confirmation, and Buy It Now → Checkout → Order Confirmation, each with and without login. Verify: required fields (Name, Address, Phone compulsory, plus Email and City) are validated on client and server; size and color are required when the product has them; COD only; the order summary shows image, name, price, quantity, total; server-side order creation uses the service-role key; guest orders work; logged-in orders are linked via user_id; My Orders shows only the current user's own orders; the confirmation page shows order number + thank-you message; cart clears after a successful order; double-submit is prevented; error messages are clear. Also check whether the confirmation_token approach (migration 012_order_confirmation_token.sql) is implemented in code and consistent with the migration file — if the code or the migration file is missing or inconsistent, report exactly what is missing and do not run anything.

6) Security and data safety sweep
Confirm every admin action calls requireAdmin(), /admin has noindex, there is no admin link on the storefront, service-role key is only used server-side, and no private table is readable by anon. Report only; fix clear bugs.

7) Cleanup
Remove unused components/imports/dead code, leftover console.log statements, and leftover placeholder or dummy data. Make sure no hardcoded test data remains in the storefront. Confirm no layout/typecheck/lint warnings remain.
